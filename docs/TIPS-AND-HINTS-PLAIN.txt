CHIP SLICER HIERARCHY — TIPS & HINTS (v1.0.0.4)
=================================================
(Plain-text version — safe to paste into a Power BI text box; no markdown tables)

GETTING STARTED
1. Drag a Category field into the Categories well (Level 1).
2. Add as many further fields to the same well as you need -- field order determines
   hierarchy depth (1st = Level 1, 2nd = Level 2, and so on). There is no level limit.
3. Click a chip to filter the report. Child chips for the next level appear automatically.
4. Click the expand icon (>) to browse a level without filtering.

FIELD WELLS
- Categories (required) .... hierarchy fields, in order; the order IS the hierarchy
- Images (optional) ........ Base64 data URI per level, same order as Categories
- Values (optional) ........ measure shown as a badge on each chip
- Tooltips (optional) ...... extra fields shown on hover, up to 5

FORMAT PANE
- Chip Style ....... layout, multi-select, leaf-only, hide blanks, default selection,
                      chip size / radius / font / gap / padding, "All" button
- Search ........... show/hide search box, placeholder, colors
- Images ........... image height, position, border radius
- Value Badge ...... show/hide, format (compact/number/currency/percent), colors, size
- Hierarchy ........ indent per level, expand icon, auto-collapse siblings, reset button
- Level 1/2/3 Colors ... independent inactive / active / parent-of-selection colors per level

IMAGES — FORMAT REQUIRED & HOW TO GENERATE THEM
IMPORTANT: The visual only accepts images embedded as Base64 data URIs.
External URLs (http://, https://, blob:, etc.) are blocked and will not render.

Accepted format:  data:image/<type>;base64,<encoded data>
Examples:
  data:image/png;base64,iVBOR...
  data:image/svg+xml;base64,PHN2...

OPTION 1 — Power Query (recommended)
Add a custom column in Power Query with this M code:

  "data:image/png;base64," &
  Binary.ToText(
      Web.Contents("https://your-storage.com/image.png"),
      BinaryEncoding.Base64
  )

This fetches the image once at refresh and embeds it permanently in the model.
No outbound requests happen when the report is open.

OPTION 2 — Python script (batch conversion)
Run this script to convert a folder of images into a CSV ready to merge with
your data:

  import base64, csv, os
  folder = r"C:\my-images"
  rows = []
  for fname in os.listdir(folder):
      if fname.lower().endswith((".png", ".jpg", ".jpeg", ".svg")):
          ext = fname.rsplit(".", 1)[1].lower()
          mime = "svg+xml" if ext == "svg" else ext
          with open(os.path.join(folder, fname), "rb") as f:
              b64 = base64.b64encode(f.read()).decode()
          rows.append({"name": fname,
                        "imageUrl": f"data:image/{mime};base64,{b64}"})
  with open("images.csv", "w", newline="") as f:
      w = csv.DictWriter(f, ["name", "imageUrl"])
      w.writeheader(); w.writerows(rows)

Import images.csv into Power BI and join it to your data by file name.

OPTION 3 — SVG generated in Power Query
For simple shapes or icons generated on the fly, build an SVG string and
encode it with Binary.ToText(..., BinaryEncoding.Base64) in Power Query.
DAX alone cannot do HTTP requests or Base64 encoding.

QUICK RULES
  OK ... data:image/png;base64,...
  OK ... data:image/jpeg;base64,...
  OK ... data:image/svg+xml;base64,...
  NO ... https://example.com/image.png  (blocked)
  NO ... blob:...                        (blocked)
  --  ... empty or null                  (ignored, no error)

TIPS & BEST PRACTICES
- Keep Level 1 categories short -- long labels wrap chip layout on narrow visuals.
- Use vertical layout for tall/narrow report canvases with many values.
- Enable "Hide blank values" if your source data has nulls in hierarchy fields.
- Use the Value Badge with compact format for large numbers (K/M/B) to keep chips narrow.
- Image chips work best with square, small (under ~64px) images for fast rendering.

SELECTION MODES IN DETAIL  (all available without a licence)
- Multi-select .......... click additional chips to add to the selection
- Leaf-only selection ... restricts clicking to the deepest available level
- Auto-collapse siblings  collapses other expanded branches when a new one is expanded

THE PRO FEATURE
- Search box ............ type to filter chips across the whole hierarchy, not just the
                          level currently visible. Enable it under "Search" in the format
                          pane. It is the only feature that requires a licence.

EXAMPLE CONFIGURATIONS
- Simple category filter: 1 field in Categories, nothing else -- behaves like a standard
  single-level slicer with chip styling.
- Product catalog browser: Category, SubCategory, Product in Categories; Images well with
  Base64 thumbnails; Values well with a Sales measure.
- Compact sidebar slicer: vertical layout, small chip height, search enabled (Pro).

TROUBLESHOOTING
- Chips not filtering other visuals -> confirm the field is present (directly or via
  relationship) in the visuals you expect to be filtered.
- Images not showing -> the Images field must contain a Base64 data URI
  (data:image/...;base64,...). External URLs (http/https) are blocked for security.
  See the "Images — Format Required & How to Generate Them" section above.
- A level not appearing -> check how many fields are in the Categories well: the field
  order is the hierarchy and there is no level limit in either tier. Check "Hide blank
  values" too, if that level has nulls.
- Colors not applying -> confirm you're editing the correct Level (1/2/3) color card; each
  level has an independent color set.
