CHIP SLICER HIERARCHY — TIPS & HINTS (v1.3.0.0)
=================================================
(Plain-text version — safe to paste into a Power BI text box; no markdown tables)

GETTING STARTED
1. Drag a field into the Categories well -- it becomes Level 1.
2. Add a second and third field to the same well. The field order is the hierarchy
   (1st = Level 1, 2nd = Level 2, 3rd = Level 3). Three levels is the maximum.
3. Click a chip to filter the report. A chip with children opens when you select it.
4. Click the arrow on a chip to open a level without filtering.
5. Format > Style template changes the look of the three levels in one click.

While you edit, a tips bar at the bottom offers the templates and "Try Pro" buttons.
Close it with the X; it comes back from Format > Style template > Show setup tips.

FIELD WELLS
- Categories (required) .... up to 3 fields, in order; the order IS the hierarchy
- Images (optional) ........ one Base64 data URI column per level, same order as Categories
- Values (optional) ........ one measure, shown as a badge and added up per chip
- Tooltips (optional) ...... extra fields shown on hover, up to 5
Up to 2,000 rows of the hierarchy are loaded.

SELECTING AND CLEARING  (all free)
- Multi-select ............ on by default; each click adds or removes a chip.
                            Off: a click replaces the selection; Ctrl+click still adds.
- Leaf-only selection ..... only the last level can be selected
- Auto-collapse siblings .. opening a chip closes the others at the same level
- Clear button (X) ........ next to the search box or drop-down bar, otherwise top-right;
                            shown only when something is selected
- All chip ................ clears the selection; its text can be changed
- Default selection ....... None, First value or These values (e.g. Spain, France),
                            matched at any level. Applied when the slicer opens with
                            nothing selected; if cleared, it stays clear until the page
                            is opened again.
THE FILTER USES THE DEEPEST LEVEL WITH A SELECTION: select Europe and then Spain, and
the page is filtered by Spain.
The selection is a Power BI filter: sync slicers, bookmarks and edit interactions work.

STYLE TEMPLATES
Classic (default) - Outline - Soft - Square - One colour - Dark.
A template fills in only what you have not changed yourself.

FORMAT PANE
- Style template ...... template, show setup tips
- Chip Style .......... layout, multi-select, leaf-only, hide blanks, default selection,
                        chip size / radius / font / gap / padding, "All" button
- Drop-down (Pro) ..... drop-down mode, label
- Search (Pro) ........ search box, highlight matches, result count, placeholder, colours
- Images .............. image height, position, border radius
- Value Badge ......... show, format (Model format / Compact / Number / Currency /
                        Percentage; Compact is the default), colours, size
- Value Heatmap (Pro) . colour chips by value, low and high colours
- Hierarchy ........... indent, expand icon, auto-collapse siblings, reset button
- Level 1/2/3 Colors .. inactive, active and (levels 1-2) parent-of-selection colours
With Format on, click a chip, a badge, the X, the search box or the drop-down bar to
format it in place.

THE PRO FEATURES
- Search box ........ type to find chips at every level; matches are marked and counted.
- Colour by value ... each chip tinted between a low and a high colour by its measure,
                      scaled PER LEVEL so a child is compared with its siblings.
- Drop-down mode .... a bar shows the selection ("All", "Spain, France", "3 selected");
                      one click opens the tree. Escape closes it. THE LIST OPENS INSIDE
                      THE VISUAL'S OWN AREA: make the visual as tall as the open list.

KEYBOARD
One Tab stop. Arrows, Home and End move between chips. Right opens a chip with children,
Left closes it. Enter or Space selects (Ctrl adds). Escape clears or closes the drop-down.
Shift+F10 opens the context menu.

IMAGES — FORMAT REQUIRED & HOW TO GENERATE THEM
IMPORTANT: the visual only accepts images embedded as Base64 data URIs.
Web addresses (http://, https://, blob:) are not loaded.

Accepted format:  data:image/<type>;base64,<encoded data>
Examples:
  data:image/png;base64,iVBOR...
  data:image/svg+xml;base64,PHN2...

OPTION 1 — Power Query (recommended)
Add a custom column in Power Query with this M code:

  "data:image/png;base64," &
  Binary.ToText(
      Web.Contents("https://your-storage.com/image.png"),
      BinaryEncoding.Base64
  )

The image is fetched once at refresh and stored in the model.
Nothing is requested when the report is open.

OPTION 2 — Python script (batch conversion)
Convert a folder of images into a CSV ready to merge with your data:

  import base64, csv, os
  folder = r"C:\my-images"
  rows = []
  for fname in os.listdir(folder):
      if fname.lower().endswith((".png", ".jpg", ".jpeg", ".svg")):
          ext = fname.rsplit(".", 1)[1].lower()
          mime = "svg+xml" if ext == "svg" else ("jpeg" if ext == "jpg" else ext)
          with open(os.path.join(folder, fname), "rb") as f:
              b64 = base64.b64encode(f.read()).decode()
          rows.append({"name": fname,
                        "imageUrl": f"data:image/{mime};base64,{b64}"})
  with open("images.csv", "w", newline="") as f:
      w = csv.DictWriter(f, ["name", "imageUrl"])
      w.writeheader(); w.writerows(rows)

Import images.csv into Power BI and join it to your data by file name.

OPTION 3 — SVG built in Power Query
Build an SVG string and encode it with
Binary.ToText(Text.ToBinary(svg), BinaryEncoding.Base64) in Power Query.
DAX alone cannot do HTTP requests or Base64 encoding.

QUICK RULES
  OK ... data:image/png;base64,...
  OK ... data:image/jpeg;base64,...
  OK ... data:image/svg+xml;base64,...
  NO ... https://example.com/image.png  (not loaded)
  NO ... blob:...                        (not loaded)
  --  ... empty or null                  (ignored, no error)

TIPS & BEST PRACTICES
- Keep Level 1 labels short -- long labels make the chips wrap on narrow visuals.
- Use the vertical layout for tall, narrow sidebars.
- Turn on "Hide blank values" if your hierarchy has blanks.
- Use the Compact badge format (K/M/B) for large numbers, or Model format to match the measure.
- Use small, square images for the chips.
- In drop-down mode, size the visual for the open list.

EXAMPLE CONFIGURATIONS
- Simple category filter: 1 field in Categories -- a flat chip slicer.
- Product catalogue: Category, Subcategory, Product; Base64 thumbnails in Images; a Sales
  measure in Values with the badge on.
- Geography with a default: Country > Region > City, Default selection = These values, Spain.
- Compact header slicer (Pro): drop-down mode plus the search box.

TROUBLESHOOTING
- Chips do not filter other visuals -> check Format > Edit interactions and the
  relationships in the model.
- Only the child filters -> by design: the deepest level with a selection is the filter.
- A level does not appear -> at most three fields; open the parent chip; with "Hide blank
  values" on, a path stops at a blank.
- Images do not show -> the column must hold a data:image/...;base64,... value.
- The drop-down list is cut off -> it opens inside the visual; make the visual taller.
- "Pro preview" watermark -> a Pro feature is on without a licence; only you see it while
  editing, readers see the free chips.
- Colours do not change with a template -> use "Reset to default" on that colour.
